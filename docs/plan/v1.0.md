## How to use this document

Same conventions as [`BOOTSTRAP.md`](../setup/BOOTSTRAP.md#how-to-use-this-document):

- Roles: **🧑 YOU** (Xcode UI, devices, App Store Connect, decisions), **🤖 CLAUDE CODE** (files, terminal, git, checks), **✅ VERIFY**.
- Marks: `- [ ]` pending, `- [x]` done and verified, `- [x] … — ⏭️ skipped: <reason>`. Findings are recorded as `Result: …` under the step.
- Steps after a PR is opened are marked at step N.2 of the next phase and committed with that phase's progress commit.
- Run it with: *"Read `docs/plan/v1.0.md` and continue from the first unchecked step. Stop at every 🧑 YOU step."*

### Standard PR cycle

Every phase ends with these steps (listed in each phase as **PR cycle**):

1. Commit: `docs: update v1 plan progress for phase N`
2. `git push -u origin <branch>` and `gh pr create --base main --title "<PR title>"` with the template filled in
3. CI `test` green (and `core-tests` from Phase 10 on)
4. Merge with rebase (author from GitHub or Claude with `gh pr merge --rebase --delete-branch`)
5. `git switch main && git pull`; the push run on `main` is green

### Definition of Done

Every feature and screen follows [WORKFLOW.md › Definition of Done](../WORKFLOW.md#definition-of-done). In short, for each screen: matches its mockup, light and dark previews, iPhone SE and Pro Max layouts, largest Dynamic Type, VoiceOver, English and Spanish strings, animations and haptics per DESIGN.md › Motion (checked with Reduce Motion), zero SwiftLint warnings, logic covered by tests.

## Instructions for Claude Code

1. All the rules in [`CLAUDE.md`](../../CLAUDE.md) and the bootstrap instructions apply: English only, never commit to `main`, never hand-edit the `.pbxproj`, zero SwiftLint warnings, no `fatalError`, no UI tests.
2. Before building a screen, read its mockup in `docs/design/mockups/` and DESIGN.md. Do not invent colors, sizes, radii, animations or haptics: use the design tokens and `Motion`.
3. Every architecture choice listed as **Decision** in a phase is drafted as an ADR by Claude Code and reviewed and accepted by the author **before** code depends on it.
4. FinTrack Pro (`~/Documents/Portfolio/Old_FinTrackPro`) is reference only. When porting a piece, state what changes and why in the PR description.
5. Business logic lives in `GuldrCore` (from Phase 10) and is tested with `swift test`; the app target keeps views, view models and system integrations.
6. One screen or one capability per PR. If a phase grows beyond ~15 files, split it and add the extra phase to the Progress table.

## Scope of v1.0.0

What ships, from [ROADMAP.md](../ROADMAP.md) and the mockups:

| Capability | Screens / surfaces | Mockup |
|---|---|---|
| Transactions: add, edit, delete, categories | Add sheet, Transactions tab | `AddTransaction`, `Transactions` |
| Dashboard: balance, month income/expenses, savings rate, recent | Home tab | `Dashboard` |
| Budgets: monthly limit per category, ring, over-budget alert | Budget tab | `Budget` |
| Analytics: income vs expenses, spending by category, period picker | Analytics tab | `Charts` |
| Home screen widgets: small and medium | WidgetKit | `Widgets` |
| Face ID lock | Lock screen | `Lock` |
| Local budget notifications | System notifications | — |
| CSV export | Settings | — |
| English and Spanish, accessibility | Everywhere | — |

Out of scope (see the roadmap): **iCloud sync — confirmed for v1.1** (models stay CloudKit-compatible and CloudKit is explicitly disabled in v1.0), Siri, iPad, other languages, multiple accounts, recurring transactions, CSV import.

### Experience principles

Native look and feel with Guldr's identity: system navigation, tab bar, sheets and controls (iOS 26 Liquid Glass) dressed with the design system — matte gold accent, serif amounts, ledger lines and the wordmark. Motion and haptics follow DESIGN.md › Motion (Phase 15): they explain changes of state, use native springs and respect Reduce Motion. Every screen has empty, loading and error states.

### What we learned from FinTrack Pro

| FinTrack Pro | Guldr v1.0 |
|---|---|
| `amount: Double` | Exact money type (Phase 9 decision) plus `currencyCode` on every transaction |
| `@Attribute(.unique)`, non-optional relationships | CloudKit-compatible models with defaults and optional relationships |
| `fatalError` creating the container | Typed `PersistenceError` and a recoverable error screen |
| Category with emoji and hex color | SF Symbol only; charts color categories by rank with `Chart1…7` (ADR 009) |
| Budget keyed by `"yyyy-MM"` string | Month key that is easy to query and timezone-safe (Phase 9 decision) |
| Widget reads a JSON snapshot in `UserDefaults` | Decided in Phase 9: snapshot vs. read-only shared store |
| `USD` hard-coded in the formatter | Currency chosen at first launch, formatted per locale |
| Calculations inside view models | Pure functions in `GuldrCore`, unit-tested without a simulator |
| Ad hoc animations and haptics per view | A motion system (tokens, patterns, haptics, Reduce Motion) in the design spec and in code |
| Biometric service `@unchecked Sendable` without explanation | Protocol-based lock service with documented isolation |

**🤖 CLAUDE CODE — Motion system**

- [ ] **15.3** Draft a **Motion** section in `docs/design/DESIGN.md` and add a `motion` group to `tokens.json`:
  - **Principles:** motion explains a change of state (something saved, a value updated, a limit crossed); it is never decoration. Native springs only; short and calm, in line with the brand voice.
  - **Tokens:** `standard` (`.smooth`, ~0.35 s) for layout and value changes, `snappy` (`.snappy`) for direct manipulation such as chips, keypad and toggles, `emphasized` (`.bouncy` with low bounce) reserved for success moments; stagger for list and chart entrances capped at ~0.25 s total.
  - **Patterns:** amounts change with `.contentTransition(.numericText(value:))`; progress bars, mini rings and the budget ring fill from 0 on first appearance; charts animate marks on period change; SF Symbols use `.symbolEffect` (bounce on save, pulse on an over-budget alert); native sheet, navigation and tab transitions are never replaced.
  - **Haptics:** `.sensoryFeedback` — `.selection` for chips and segmented changes, `.impact(weight: .light)` per keypad key, `.success` on save, `.warning` when a budget is exceeded, `.error` on a failed unlock.
  - **Reduce Motion:** fills and transitions become opacity cross-fades or are skipped; numeric transitions stay (they are not motion-heavy); haptics stay.
